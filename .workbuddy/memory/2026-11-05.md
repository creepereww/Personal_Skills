## 推送失败根因订正：不是「路线时通时断」，是 Watt Toolkit 反代 + PortableGit 没了 CA

提交后推送失败，代理与直连**都**报同一个 `SSL certificate OpenSSL verify result: unable to get
local issuer certificate (20)`。两条路线同一个 SSL 错 = 不是路线问题。

诊断链：
1. `nslookup github.com` → 真实 IP 20.205.243.166（DNS 没被改）→ 差点误判成「网络恢复」
2. .NET 建连实测：`RemoteEndPoint = [::ffff:127.0.0.1]:443`，`issuer = CN=SteamTools Certificate`
   → Watt Toolkit 的 GitHub 加速开着，反代到本机自签证书
3. 查系统根证书：SteamTools 根证书确实装在系统信任库（3 个副本，2027 到期）
4. 关键第二重坑：PortableGit 1.3.0 **没有 mingw64/ssl 目录、没有 ca-bundle.crt**（D:/Git 也没有）
   → 仓库里 10-21 设的 `http.sslbackend=openssl` 对任何 HTTPS 都报 (20)，与劫持无关

解法（已落地，无需每次带参数）：
```
git config http.sslBackend schannel
git config http.schannelCheckRevoke false
```
schannel 走 Windows 证书库 → 认 SteamTools 根证书；吊销检查因 CRL/OCSP 不可达而关。
实测无参数 `git ls-remote` 直接通；提交 9c16667 已推上远端（复核一致）。

machine 档 v0.16：订正「schannel 要改 openssl」这条反向结论、判据改为「看实际端点/证书 issuer
而非 DNS」、补一条三行定位脚本，desc 压到 498。
