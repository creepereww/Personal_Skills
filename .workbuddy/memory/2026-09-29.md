## 改造：脚本不再硬编码本机事实

病根：脚本把「这台机器的事实」写死了，换机器就不成立。两处：

1. **git 路径** —— `sync.ps1` 候选列表只有 PortableGit 1.2.0 和 `C:\Program Files\Git`，公司电脑实际用 `D:\Git`，能跑通属侥幸。
2. **client 安装判定** —— 旧 `link.ps1` 只要 `enabled: true` 就无脑建目录，于是在没装 opencode/豆包的机器上凭空造空壳目录。

改法：
- 新增 `scripts/_common.ps1`：`Get-GitExe`（`$env:SKILLS_GIT` > PATH > 常见位置）、`Test-ClientInstalled`（`detect` 规则 > 默认看 skills 目录的父目录）、`Get-ClientPlan`。
- `routing.json` → `_version: 2`，各 client 加 `detect` / `detect_any`；`detect: []` 表示永远视为已装（workbuddy 用这个）。
- `link.ps1` 加 `-Force` / `-ListClients`；没装报 `NOTFOUND` 跳过且不建目录。
- `sync-preferences.ps1` 同样只给已装的 agent 分发，加 `-Force` / `-DryRun`。

## 拆解 local-wgc-machine：通用 / 机器专属两层

原 skill 标着「**本机** WGC_MACHINE」却住在 `store/local/`（跟随 Git 同步），
于是公司电脑上读到的机型、git 路径、网络结论**全是家那台的** ——
其中「`github.com:443` 超时」与实情（**通**）完全相反，会误导人去折腾 SSH 和代理。

拆成：

| 新的 | 内容 |
|---|---|
| `store/local/local-windows-shell-conventions` | 跨机器通用：MSYS vs 原生路径、junction 建删、命名正则、主机名大小写、客户端目录表 |
| `store/machine/wgc-work1-px/` | 公司电脑：Lecoo / `D:\Git` / 网络**正常** / Everything 1.4.1.1029，**无 es** |
| `store/machine/wgc/` | 家里那台：MECHREVO / `D:\APP_MAGIC` / 网络**不通**需 SSH / es 已装 |
| `store/machine/wgc/NOTE.md` | 说明目录名为何必须等于主机名 |

**配套机制**：
- `link.ps1` 扫 `store/machine/`，用 **`-ieq`** 匹配主机名 —— `%COMPUTERNAME%` **大写返回**而目录名按命名规范全小写，用 `-eq` 会**永远匹配不上**（实测确认）。
- `routing.json` 加 `host_aliases` 临时别名（主机名改了但没重启时借道）。**本机这条是临时的，重启后要删。**

## 判断「上游原样快照」该放哪

`easyeda-api`（今天 13:36 用户自己落的，`easyeda/` 上游快照）暴露了规则冲突：
它落在 `store/fork/` 但**没做任何本地改动**，于是 `audit.ps1` 按 fork 全套规范判它
「缺 version / desc 879>500 / 747 行」三个告警。

**结论：上游原样快照放 `store/cache/`，不放 `fork/`。** 理由：
- `fork/` 按定义要守本地规范（必须有 `version` 等），而原样快照改了就不是原样了
- `audit.ps1` 对 `cache` 只查「有没有 SKILL.md / desc 超 1024」—— 正是原样快照该受的待遇
- 代价：实体不进 Git，**溯源要转录到 `registry.json`**（cache 里的 `.upstream` 会被下次 `pull -Force` 覆盖）
