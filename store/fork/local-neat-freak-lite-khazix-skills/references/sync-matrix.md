# 变更影响清单（非代码项目版）

> 由 `SKILL.md` 第二步按需引用，**不进 Agent 上下文**。
> 原版 `sync-matrix.md` 是"代码变更类型 → 要改哪些文件"，主体是 API / 环境变量 / CI。本版换成非代码项目里常见的事实变更，并补了原版没有的「记忆层」影响。

## 用法

第二步识别变更时，遇到不确定的改动先查这张表。**不确定就两边都写**——重复在第三步会被合并掉，漏了就再也想不起来。

## 事实变更 → 要动哪些地方

| 本次发生了什么 | 要动哪些地方 |
|---|---|
| **新定下一条规则** | 规则文档「命名 / 分类 / 编号」块 **+** 记忆对应条目 **+** 说明文档（若影响用法） |
| **改了目录结构 / 移动了文件** | 规则文档「目录结构」块 **+** docs 结构说明 **+** 所有引用旧路径的链接 |
| **改了命名规则** | 规则文档 **+** docs 结构说明 **+** 记忆里引用旧命名的条目 |
| **新增一条红线 / 禁区** | 规则文档「硬边界」块 **+** 「AI 行为守则」块 **+** 删掉与之冲突的旧记忆 |
| **某个任务 / 待办完成了** | 删掉对应记忆条目；结论值得长期保留的，毕业进 docs |
| **踩了一个新坑** | 先记 `feedback_`；同一主题第 3 次出现 → 毕业进规则文档「常见陷阱」 |
| **一条知识稳定下来了** | 走毕业：内容进文档，原记忆缩成指针或删 |
| **改了某个目录 / 文件，别处引用了它** | **两边都要改**——跨目录 / 跨项目是最常见的漏改 |
| **改了说明文档里的操作步骤** | 说明文档 **+** docs 操作手册 **+** 规则文档里的命令速查 |
| **时间相关的表述** | 一律改成绝对日期 `YYYY-MM-DD` |

## 三条判断原则

1. **两边都写优于只写一处** —— 规则和记忆是不同受众，不能互相替代
2. **跨目录改动默认两边都要动** —— 不要假设改了一边另一边就不用管
3. **记忆层问一句：这条该留在这吗？** —— 事件记录删、稳定知识毕业、重复内容合并
