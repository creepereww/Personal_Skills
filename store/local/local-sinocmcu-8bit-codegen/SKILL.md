# 晟矽微 8 位 MCU：IO 初始化与宏代码生成

> **给改我的人**：成熟度 `v0.x`（完善中）→ 可直接改，改完回报"改了哪个文件、改了什么"即可。
> 本 skill **跨机器通用**：**别写死**本机磁盘路径、端口、具体工程名与器件位号 —— 那些属于项目，
> 放项目工作区。仓库规则见 `local-skills-hub`；脚本约定见 `local-script-first`。

## 范围与边界

**输入有两份**：

1. **嘉立创 EDA 网表**（连通性真值）—— 出 IO 层代码。
2. **屏幕图纸**（段码屏内部接法）—— 出屏幕驱动代码。**没有就先不出这一段**，别猜、别硬编。

**输出 = 一块方案板的 IO 层代码 + 屏幕驱动代码**：

**A. IO 层代码**（只要有网表就能出）：

1. `INIT_GPIO()` —— `IOP/OEP/PUP/PDP` 寄存器值 + 中断使能调用
2. 输入宏 / 输出宏（`PIN_xxx`、`xxx_INTERRUPT_ENABLE`）
3. 屏幕宏（LED **查理复用**：线方向 / 电平 / 输出宏；**只需知道几根线**，不需要屏内部接法）
4. 雾化 PWM 通道选择（`SMOKE_PWM_*`）

**B. 屏幕驱动代码**（**要屏幕图纸**；只给网表是出不来的）：

5. `DisplayScanService()` 扫描函数 + 变量↔符号集对照注释 + 符号宏 / 应用层别名（见「段码屏扫描」）

**只做上面这些。** 别的驱动、业务逻辑一律不写 —— 用户会单独给模板，照模板改，别自作主张补函数。
缺图纸时**只交 A、并明确说明 B 待图纸**，不要拿模板里的示例表凑数。

## 五步流程

| 步 | 做什么 | 谁做 |
|---|---|---|
| 1 | 网表 → 引脚表（端口 / 物理脚 / 引脚名 / 网络 / 复用） | **脚本** `pinmap.py` |
| 2 | 判定每脚功能：方向 / 初值 / 上下拉 / 中断 / 角色 | **模型 + 用户确认** |
| 3 | 算 `IOP/OEP/PUP/PDP` 位值 | **脚本** `gpio_gen.py` |
| 4 | 套模板出码 | **脚本** `gpio_gen.py` + `templates/` |
| 5 | 回读核对（宏名一致性、寄存器位、与网表对照） | **脚本自检 + 模型复核** |
| 6 | 段码屏定义 → `DisplayScanService()` + 符号/应用层宏 | **脚本** `display_gen.py`（**前置：拿到屏幕图纸**；没图纸就跳过这步，只交第 1~5 步的产线） |

第 1、3、4、5、6 步是确定性的，交给脚本；**只有第 2 步要动脑**，且结论要让用户过目。

## 第 2 步：判定清单

按网络名/引脚名先预填，再人工确认。**表里的 `role` 决定生成哪段宏**：

| 网络特征 | func | 方向 | 初值 | 上下拉 | 中断 | role |
|---|---|---|---|---|---|---|
| `LED_PINn` | `LEDn` | out | 0 | — | no | `led` |
| `PWM_OUT_CTL n`（雾化驱动） | `HEATn_CTL` | out | **1**（上电关断） | — | no | `pwm` |
| `KEY_MI` / 咪头 | `KEY_MI` | in | 0 | — | **yes** | `in` |
| `CHG_VCC` / `VBUS` / `USB` | `USB_IN` | in | 0 | **down** | **yes** | `in` |
| 无网络（悬空） | — | **out** | 0 | — | no | 空 |
| 其他 | 待确认 | 待确认 | — | — | — | — |

**两条硬口径（用户定的，别改）**：

- **未用到的 IO 一律 output**，初值低电平。（`PCK/PDT` 也一样：烧录时由**烧录选项**自动切方向，代码里不体现、也不必定义宏。）
- **输入脚**的 `IOP` 位写 0。

**LED 线只进屏幕段**：`role=led` 的脚不另出 `PIN_LED_LINE*`／`PIN_LEDn` 输出宏，避免和屏幕段指向同一批脚造成两套宏。
确实需要两套时，把该行 `role` 写成 `out,led`。

## 寄存器口径

- 一个端口一位：**`Pxy` → 寄存器 `x`（0/1/2）的第 `y` 位**（`IOPx`/`OEPx`/`PUPx`/`PDPx`）。位序用旧工程值反推验证过。
- `OEPx`：**1=out，0=in**。`PUPx`/`PDPx`：1=使能上/下拉。
- 芯片有**逐脚位别名**：`PxyD`(电平) / `PxyOE`(方向) / `PxyKE`(中断使能) —— 屏幕宏等直接位操作，不必写整个寄存器。
- 引脚名格式是 `P06/PWM2/AN6`、`[PCK0]/P11` 这种斜杠串，`Pxx` 有的在末尾、有的被 `[]` 修饰 —— 解析取**最后一个**合法 `P[0-2][0-7]`。

脚本只依赖 Python 标准库（本机 Node 起不了子进程，别用 node）。

| 脚本 | 什么时候跑 |

| `scripts/pinmap.py <netlist.enet.json> [-o pins.csv] [--mcu U3]` | 步骤 1：网表 → 引脚表（判定列已预填猜测）。用法见 `--help` |
| `scripts/gpio_gen.py pins.csv [-o out.c] [--tpl-dir templates]` | 步骤 3+4：算寄存器 + 套模板出码。用法见 `--help` |

| `scripts/display_gen.py segmap.csv [--pins pins.csv] [-o display.c]` | 屏幕驱动：段码屏定义 → `DisplayScanService()` + 符号/应用层宏。用法见 `--help` |

`python export_connection.py <工作目录>/<项目>/ --project <项目> --mode netlist`。

## `pins.csv` 字段

`port,phys,pin_name,net,func,dir,init,pull,irq,irq_macro,role,note`

- `port` 必填（`P00`…`P21`）；**没出现在表里的脚**按"未用"处理（output、低电平）。
- `dir`∈`in|out`；`init`∈`0|1`（只对 out 有意义）；`pull`∈``(空)`|up|down`；`irq`∈`yes|no`。
- `irq_macro`：中断宏的**完整主干**，空则用 `func` + `_INTERRUPT`（如 `KEY_MI` → `KEY_MI_INTERRUPT_ENABLE`）。
  模板沿革里有 `PIN_USB_IN` 却配 `USB_INTERRUPT_ENABLE` 这种主干不一致的，用这列填 `USB_INTERRUPT` 精确对齐 —— 别让它自动拼成 `USB_IN_INTERRUPT_ENABLE`。
- `role`∈``|`in`|`out`|`led`|`pwm`，**可逗号组合**（如 `out,led`）。`in`→输入段，`out`/`pwm`→输出段，`led`→屏幕段。
- `SMOKE_PWM_T*` 由 **role=pwm 的脚**的复用名决定（不是"引脚名里有 PWM 就置 1"—— 同脚常兼 LED 线）。

## 段码屏扫描（屏幕驱动）

**怎么亮的**：LED 查理复用。扫描每轮把**一条线**拉低当共阴极，这条阴极下所有"段位为 1"的**阳极线一起拉高** —— 所以一轮同时点亮多盏，靠刷新率骗眼睛。
`SEG_Cnt` 轮转，每轮开头先把所有线置高阻（`LEDn_IN`）再重新驱动，避免上一轮的残留。

**生成的判定逻辑是纯查表**：`阴线 → 该阴极下 [(段位, 阳线)] 列表`。
`if (段位) { 阳线_OH; }`，另有本段位对应的 `阴线_OL;`。

**表从哪来**：屏是**外接件**，网表里只有通孔焊盘（`LED_PIN1..5`），看不到屏内部接法 ——
必须从**段码屏图纸/规格书**读。别按几何顺序硬编。

### 怎么从屏的原理图读出 (阴线, 阳线)

图纸通常长这个样子：屏内部每盏灯画成一个竖放的二极管符号，**两端各标一个数字**＝屏的脚号，
二极管旁边标段名（`A2`/`B1`/`K1`…）。读法：

1. **先定极性**：看二极管符号的横杠在哪端 —— 横杠（尖端那一侧）＝ **阴极**，另一端＝阳极。
   本族图纸把横杠画在**上端**（三角形尖端朝上），所以 **上脚号＝阴极，下脚号＝阳极**。
   图上符号很小、肉眼容易看反，**用像素探针确认**：取该竖线所在列，逐行量三角形两边的间距，
   间距**向下变大** ⇒ 尖端在上（横杠在上）；反之亦然。
2. **逐灯读**：每盏灯 = (阴极脚号, 阳极脚号, 段名)。脚号 1..5 ↔ 板上的 `LED_PIN1..5` ↔ `LED1..LED5`。
3. **按阴极分组**，就是 `case 1..n`；每组内的阳线按线号升序排（模板风格）。
4. **自检**：n 线查理复用共 n×(n−1) 盏，每根线当阴极时**恰好**挂着另外 n−1 根线。
   生成的表若少了/重了，一定是读错了。校验方法：把表里所有 (阴极,阳极) 有序对去重，应等于 n(n−1)。

`segmap.csv` 列 `kind,name,cathode,anode,bit,value,symbol,comment`：

| kind | 用什么列 | 含义 |
|---|---|---|
| `scan` | `cathode` `anode` `bit` `symbol` `comment` | 一盏灯：共阴极线 / 阳极线 / 段数据位名 / 符号集名 / 注释（如 `A2:  PIN3(+)`） |
| `icon` | `name` `value` `comment` | 符号宏：`#define <name> <value>` |
| `app` | `name` `value` `comment` | 应用层别名：`#define <name> <value>` |

- `bit` 是应用层段数据变量的**位名**（`A0`/`B0`/`C0` 这种），**同一 bit 允许出现在多行** —— 屏的接法可能让一个段位在不同阴极相位下点亮不同的灯（示范工程里同一段位就用了两次）。脚本会报重复段位数，别当错误。
- `symbol` 只喂给文首的「变量 ↔ 符号集」对照注释，可自由填（同一变量内多个符号集用 `/` 分隔）。

### 位名与符号集约定（用户定的口径）

**段名（`A2`/`B1`/`K1`…）是屏图纸给的，每块屏都不一样；位名（`A0..A7`/`B0..B7`…）是自定的。**

1. **同一符号集放同一变量** —— 屏上一个显示符号（一位数字、一组图标）的所有段，进同一个段数据变量。
2. **16 位的量拆两个变量**：`A` 放高位 8、`B` 放低位 8（如两位数码管的段数据）。
3. **位名首字母 = 变量**：`A*`→`Seg_SEGData1`、`B*`→`Seg_SEGData2`、`C*`→`Seg_SEGData3`…
4. **定义完要能看出来哪个变量代表哪一符号集** —— 脚本据 `symbol` 列在文件头自动生成对照注释；这也是给应用层用的索引。
5. **零散符号（凑不成一位数字的那些）统一塞进一个变量**（通常是最末一个，如 `Seg_SEGData3`，8 位）——
   位名自定、怎么排都行；但**定义完必须用「符号宏定义」段给每个位起语义名**，应用层只认宏，不直面 `C0`/`C1`。
   例：`#define SYM_B1 C0` / `#define ICON_K1 C2` …（右值就是段数据位名）。宏名随屏上实际显示的符号来定。
6. **应用层别名**（`kind=app`）把「变量 ↔ 显示内容」写成一行宏，例：
   `#define Dis_Elequa10 Seg_SEGData1.allbits //数码管高位两位数据`、`#define Dis_ICON Seg_SEGData3.allbits //零散符号`。
   第 5、6 两条的 `icon`/`app` 行由 `display_gen.py` 从 `segmap.csv` 渲染进 `display_macros.c.tpl`，版式照用户给的样子。

**怎么判「一个符号集」**：看屏玻璃（图纸上画段位置的那一块），**位置在一起、构成同一个显示符号的那组段就是一个符号集**。
例：某屏左边数字的段是 `A2/F2/B2/G2/E2/C2/D2`（全带 `2`）、右边数字是 `A3/…/G3`（全带 `3`）、
`B1/C1` 单成 `1` 符号、`K1..K4` 是 4 个方框图标 —— 就是 4 个符号集。
**别把同一位数字的段拆到两个变量里去**。
- 阴极顺序 = 线名自然序（`LED2` 在 `LED10` 前），`case 1` 对应第 1 根线，最后一档自复位 `SEG_Cnt = 0;`。
- 段数据变量的声明（`volatile bitflag Seg_SEGDataN;`）与 `SEG_Cnt` 由应用层提供，**本流程不生成**。

## 常见坑

1. **寄存器别手算** —— 位序、线数、L/H 反了，返工过好几轮。跑 `gpio_gen.py`。
2. **宏名一致性**：`#define X_INTERRUPT_ENABLE` 与调用点 `X_INTERRUPT_ENABLE;` 必须逐字相同。出过一次定义 `USB_INTERRUPT_ENABLE`、调用写 `USB_IN_INTERRUPT_ENABLE`。用 `--check` 抓。
3. **屏幕是查理复用**：一盏灯跨**两根线**（阳极线拉高 + 阴极线拉低），**没有**"单脚开关一盏灯"的宏。宏只提供"线 k 高/低/输出/高阻"。
4. **LED 线数看网表**，不是看模板 —— 模板可能是 8 线，实板可能只有 5 线（`LED_PIN1..5`）。多出来的别硬凑。
5. **不是所有引脚名里的复用功能都在用**：`P06/PWM2/AN6` 可能当 LED 线，`P01/PWM3A/AN11` 可能当 USB 检测 —— 复用名只作线索，实际用途以网络名为准。
6. **段码屏的段位映射别猜** —— 屏是外接件，网表看不到内部接法。有屏的原理图就按上面「怎么读」那节推
   （极性用像素探针定，别靠肉眼）。**位名按「位名与符号集约定」自己定**，不必问用户；但**符号集怎么划分要看屏玻璃的位置**，
   划错了就说不上「同一符号集放同一变量」。
   图纸上的注释（SEG 号等）若与系统性口径冲突，以**图上的段名 + 线对**为准。
7. **写 `.c` 要固定 LF**：`Path.write_text()` 在 Windows 默认转 CRLF，跟工程里的 LF 文件 `diff` 会全篇假差异。用 `newline="\n"`。
8. 审查/改设计属于"大改"，先说明改哪个文件、删什么、加什么，等确认再动手；**生成只读的代码文件不算改设计**。
