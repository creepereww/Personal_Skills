# 从零建立审查报告模板（非代码项目版）

> 由 `SKILL.md`「从零建立规则文档」第 2 步按需引用，**不进 Agent 上下文**。
> 相对原版改了三件事：① "代码事实"一列换成"**交付物事实**"；② 删掉配置文件 / CI/CD / 项目元数据 / CHANGELOG / 代码逻辑这类代码专属审查板块；③ **新增「记忆层审查」**——这是精简版的核心，原版没有。

## 报告结构

**项目概况 → 一致性问题（核心）→ 逐层审查 → 操作清单**

一致性优先于完整性：先找"文档说的跟实际不一致"，再找"缺了什么"。错误信息比缺失信息危害更大。

## 完整示例

```
## 从零建立审查报告

### 项目概况
- 项目类型：文件整理 / 知识库 / 纯文档（选一个）
- 事实基准：<这次拿什么当基准 —— 整理后的目录树？那个 HTML 文件？现有文档？>
- 规模：~N 个顶层目录、~N 个文件、现存 N 个 .md
- 事实提取要点：<盘点出来的硬事实，每条要具体到可以逐条比对>

---

### 一致性问题（核心）

| # | 文件 | 问题类型 | 文档描述 | 交付物事实 | 严重度 |
|---|------|----------|----------|-----------|--------|
| 1 | 整理规则.md | 路径不存在 | "截图放 Screenshots/2026/" | 实际是 Screenshots/2026-09/ | 🔴 高 |
| 2 | 整理规则.md | 命名规则过时 | "统一用 日期_主题 命名" | 实际多为 截图_序号 | 🟡 中 |
| 3 | 记忆 MEMORY.md | 规则冲突 | "根目录不许新建文件夹" | 另一条记忆写"临时文件放根目录" | 🔴 高 |
| 4 | README.md | 步骤不可执行 | "运行 sort.py" | 该文件不存在 | 🔴 高 |

严重度：🔴 高 = 照着文档做会出错；🟡 中 = 信息不准但不致失败；🟢 低 = 风格/格式问题

---

### 规则文档审查

**文件状态**：❌ 不存在 （或：⚠️ 存在但不一致，N 行）

| 板块 | 状态 | 需写入的事实 |
|------|------|-------------|
| 1. 这份规则管什么 | ❌ 缺失 | 1-3 行定位 |
| 2. 目录结构 | ❌ 缺失 | 各顶层目录放什么、不放什么 |
| 3. 硬边界与红线 | ❌ 缺失 | 只读扫描 → 确认 → 回收站 → 备份 |
| 4. AI 行为守则 | ❌ 缺失 | 操作前必须做什么 |
| 5. 命名 / 分类 / 编号规则 | ❌ 缺失 | 实际在用的命名法 |
| 6. 常见陷阱 & 已知问题 | ❌ 缺失 | 会再踩的坑 |

**建议**：从零创建，6 块全部补齐（完整 11 板块清单见 `doc-standards.md`）。

| 10. 致谢 / 相关项目 | — | 可选 |
| 11. 其他 | ✅ 一致 | — |

| 建议文档类型 | 状态 | 需写入的事实 |

### 散落 .md 文件审查

| 文件 | 状态 | 处理建议 |
|---|---|---|
| 旧整理笔记.md | ⚠️ 与规则文档内容重复 | 合并进 docs/，原件删 |
| TODO.md | ⚠️ 已过期 | 更新或删 |
| 桌面/readme.txt | ⚠️ 位置不对 | 迁入项目目录 |

### 记忆层审查（精简版核心）

| # | 记忆条目 | 问题 | 处理建议 |
|---|---|---|---|
| 1 | feedback_误删文件 | 同一主题第 3 次出现 | 毕业进规则文档「硬边界与红线」 |
| 2 | project_上次整理完成 | 事件记录，已完结 | 删；结论进 docs，过程进 git log |
| 3 | reference_目录结构 | 与规则文档重复 | 缩成一行指针 |
| 4 | 某条记忆 | 含"上周""最近" | 改成绝对日期 |

**体量体检**：
- 记忆索引：N 行 / N KB（红线 ≤200 行且 ≤25KB）
- 记忆目录 vs 文档目录：N KB vs N KB（**记忆不应更大**，倒挂说明该毕业的没毕业）

|---|---|---|---|---|
```

## 状态标记说明

- ✅ **合格** — 内容准确且与交付物一致
- ⚠️ **不一致** — 存在但与交付物事实不符（**必须列出具体不一致项**）
- ⚠️ **不完整** — 存在但遗漏了事实（**必须列出遗漏项**）
- ❌ **缺失** — 不存在或为空
- **— 不适用** — 该板块对此项目非必须

## 从报告到操作清单

报告输出完，紧接着输出「待执行操作清单」，按优先级分组，末尾明确写"请确认以上操作"：

```
### 🔴 先修不一致
- [ ] <文件> — <改什么>

### 🟡 新建文件
- [ ] <文件> — <装什么>

### 修改 / 迁移
- [ ] <文件> — <改什么>

### 记忆毕业
- [ ] <记忆条目> → <目标文档>
```

**顺序原则**：先修不一致（错误信息比缺失信息危害大）→ 再新建 → 再修改 → 最后迁移清理。
**收到确认才动手**，部分确认只做确认的部分。
