# 文件整理查重

**一句话**：先盘点、再查重、后归类。顺序不能反——跳过盘点就会漏文件，跳过复核就会删错。

这套流程针对的是「几万个文件、跨多个盘、来源混乱」的场景。少量文件的整理用不上它。

## 一、四条不可违反的原则

**1. 一组重复只能删副本，不能全删**
查重的目的是去掉冗余，不是删掉这类文件。任何"整组删除"都必须由用户逐组确认。

**2. 目录元数据不单列处理**
`desktop.ini`、`Thumbs.db`、`.DS_Store` 这类是**目录的属性文件**，必须跟着所在目录一起迁移。
把它当"垃圾文件"单独挑出来移走，会让两边都不完整：原目录丢了图标/显示名，新位置少了一部分。
垃圾名单里只放真正的缓存和临时产物。

**3. 删除一律走隔离区，不直接删**
移到 `_已删除_待清空/` 并保留原相对路径，同时写日志（源、目标、大小）。
用户抽查确认后再彻底清空。日志用**追加**模式——多次执行不能覆盖历史，否则回滚会失效。

**4. 说清"归类"的层次**
有两种截然不同的整理，开工前必须先对齐是哪一种：
- **目录级映射**：整个源目录搬到目标分类下，目录内部结构原样保留
- **文件级类型归并**：按扩展名/内容重排，所有照片进照片目录、所有视频进视频目录

用户说"整理"时往往想的是后者，但后者会打散原有组织（比如按项目、按年份的目录）。
默认做目录级映射，除非用户明确要求类型归并。

## 二、流程

### 阶段 1：盘点（建立可信台账）

递归扫描全部文件，记录 `路径 / 大小 / 扩展名`，单独记录**无法访问**的文件。

为什么先盘点：后面所有的"少了没有""多了没有"都要拿这份台账做基准。
没有基准，最后无法证明零丢失。

产出：`scan_files.csv`（全量）+ `scan_errors.txt`（拒绝访问的条目）。

遇到权限问题（常见于旧系统 SID 的只读文件）先修复 ACL 再扫，不要跳过——
跳过就会在台账里留下黑洞。

### 阶段 2：MD5 全量查重

按**文件大小**分组（同大小才可能是同一份），组内算 MD5，找出内容完全相同的组。

**保留规则要显式设计**，不能随机。推荐按这个优先级取"保留方"：

| 因素 | 倾向 |
|---|---|
| 路径层级 | 浅的优先（说明是主动整理的，深层多半是备份） |
| 目录语义 | `照片/文档` 优先于 `back/备份/旧` |
| 修改时间 | 在以上都相同时，新的优先 |

产出 `dup_move_plan.csv`：**每组明确标出保留哪一个、移走哪些**，让用户能一眼复核。

### 阶段 3：复核校验（搬家前）

移动前跑一次孤儿检查：对每个待移走的文件，确认它所属组里**确实还有一份被保留**。
再做抽样：随机抽 300 个待移走文件，重算 MD5 与保留方比对，必须 100% 一致。

这一步是最后一道保险。跳过它，一旦分组逻辑有 bug 就会造成真实丢失。

### 阶段 4：执行移动 + 还原误判

移动完成后立刻做一次"误判回收"：把被当作垃圾移走、但实际是占位/索引文件的条目
（例如音乐软件的占位歌词、空壳缓存文件）还原回原位。

判据通常是**文件极小（≤200 字节）且删除后会导致源目录结构变化**。

### 阶段 5：目录级归类

建 `源目录 → 目标目录` 的映射表，整目录搬迁，保留内部结构。

映射表按**语义**而非路径命名，例如：

```
H:\back\多媒体库    → G:\02_视频\多媒体库
H:\back\software    → G:\05_软件工具\软件备份
G:\Favorites        → G:\04_文档\收藏夹
```

映射表本身就是交付物——让用户能对照检查，也便于回滚。

**注意：归类移动之后，之前生成的查重结果里所有路径都会失效。**
凡是依赖路径的产物（查重清单、审阅工具）都要在数据变更后**重新生成**，
否则会出现"文件不存在"和统计错乱。

### 阶段 6：完整性校验与清理

- 跨盘文件抽样校验：图片/视频逐个读文件头或解码，确认无损坏
- 缓存与垃圾：只在用户确认后删除，且同样走隔离区

## 三、常见的坑

| 坑 | 后果 | 对策 |
|---|---|---|
| 归类后再用旧清单 | 路径失效、统计出负数 | 数据变更后重新生成所有依赖路径的产物 |
| 用户先删了待处理目录 | 后续还原方案全部失效 | 给出"先还原、后删除"的方案时，必须**明确提醒先别删** |
| 移动中断产生残缺副本 | 半截文件留在目标位置 | 移动后校验大小一致；异常时从源盘原件补齐，改名加 `.broken_时间戳` 而不是直接覆盖 |
| 一次性移动几万个文件 | 中途失败难以定位 | 分批执行 + 逐批记录日志，失败单独导出成 CSV 供重试 |
| 用文件大小代替内容比对 | 同名不同内容被误判 | 必须过 MD5 |
| **在 PowerShell 数组字面量里现场拼接参数**：`@('a', '/LOG:' + $x, 'b')` | **逗号优先级高于 `+`**，`/LOG:` 与路径被拆成两个独立参数。robocopy 收到孤立的 `/LOG:` 就报 `Invalid Parameter #17` 并**直接退出，一个文件都不复制** | 先在数组**外面**算好：`$logArg = '/LOG:' + $x`，再 `@('a', $logArg, 'b')` |
| 只敢测"参数组合"不敢测"真实代码路径" | 直接用命令行手打参数测试通过，但脚本里的数组构造方式有 bug——测试没覆盖到就发现不了 | 测试要调用**与正式脚本相同的构造逻辑**（同样的数组、同样的变量），否则等于没测 |
| 用 `robocopy /LOG:` 记中文路径的日志 | 中文文件名在日志里全是乱码 | 改用 **`/UNILOG:`** —— robocopy 会写 UTF-16(带 BOM) 日志，任何编辑器打开都正常。**换 PowerShell 7 治不了这个**：robocopy 是 ANSI 程序，输出编码由系统代码页决定，与控制台解释编码错配才是乱码根源 |
| robocopy 逐条列出每个文件 | 控制台刷屏，且中文路径大量乱码 | 加 `/NFL`（不列文件名）+ `/NDL`（不列目录），只留摘要表；失败项仍会单独列出，不会漏 |
| 用 Python f-string 生成 PowerShell 脚本 | PS 的 `"{0}"` 被当成表达式 `0` 求值，静默替换成字面量 | 用普通字符串 + `.replace('__KEY__', val)`；含格式符的段落绝不能是 f-string |

## 四、交付物

一次完整整理应该留下这些（都在工作区目录里）：

- `scan_files.csv` / `scan_errors.txt` —— 盘点台账
- `dup_move_plan.csv` —— 查重方案（含保留/移走标注）
- `organize_log.csv` / `organize_failed.csv` —— 归类执行与失败记录
- 映射表 CSV —— 便于用户核对和回滚
- 回滚脚本 —— 按日志反向移动
- 最终报告 HTML —— 用户视角的成果说明

## 五、脚本

`scripts/scan_and_hash.py` —— 阶段 1+2 的通用实现：扫描盘点并按大小分组算 MD5。
用法见脚本头部注释。归类映射表因项目而异，不提供通用脚本，按阶段 5 的说明手写映射表即可。
