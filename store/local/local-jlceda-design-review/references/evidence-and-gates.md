# 证据口径与审查门禁

> 方法论来源：`智构 · EasyCirq` 的「阶段门禁 + 六态证据」体系（Apache-2.0），
> 按**只读审查**场景改编 —— 它原本是建板交付流程（G0–G6），这里映射成审查门禁（R0–R6）。
> 不改我们的能力边界：仍然是只读、不改设计。

---

## 1. 五态证据：一次"审查"要分别成立的五件事

> 原体系原话：**"调用成功、写入成功、保存成功、重新打开后仍存在、质量通过是五件事，
> 缺一项就是 `NOT RUN`/`unknown`，不能合并成'完成'。"**

审查场景的对应五态（**逐态单独成立，不许合并成"已审查"**）：

| 态 | 含义 | 怎么验 | 缺了怎么记 |
|---|---|---|---|
| **① 读取** | 器件/网络真的读到了 | `sch list` 返回非空；**返回 0 不一定是空页**（可能是文档处于非同步态） | `NOT RUN` |
| **② 编译** | ENET 网表产出成功 | `netlist.enet.json` 存在；器件数与 `sch list`（扣掉屏蔽区）能对账 | `NOT RUN` |
| **③ 交叉验证** | 关键结论有两个不相关来源 | ENET ↔ `sch_parts`；`sch check` ↔ `bridge-check`；DRC ↔ 坐标实测 | `待确认` |
| **④ 回读** | 换一次读取后结论不变 | `doc reload` 后再读，或换命令（`sch list` ↔ `sch connectivity`）复核 | `待确认` |
| **⑤ 几何/质量** | 几何类检查真的跑完 | `sch check` 有 `summary`、`pcb_drc` 有 `violations`；**跑不起来 ≠ 0 问题** | `NOT RUN` |

**最容易自欺的两处**（都真踩过）：

- `sch list` 静默返回 0 个器件 —— 命令成功、退出码 0，但什么都没读到；
- `sch check` 返回 `null` —— 不报错，但检查根本没执行。

⇒ 见到"0 个问题"先问一句：**是查过没发现，还是没查成？**

## 2. 状态语汇：每条结论必须挂一个

| 状态 | 用法 |
|---|---|
| `已验证` | 写明**方法 / 对象 / 版本 / 适用范围**。例：「ENET 网表 + bridge-check 双源确认，2026-10-29，v1.9.0」 |
| `有条件满足` | 写明成立前提。例：「VBAT ≥ 3.4V 时满足；低于则轨跟随电池」 |
| `不满足` | 已观察到违反约束或计算不满足 |
| `待确认` | 缺输入 / 缺规格 / 缺工具，**尚未执行** |
| `不适用` | **必须写理由**（例：「TFT1.9 是 NC 脚，无需接地」） |
| `NOT RUN` | 检查器跑不起来或依赖缺失，与"待确认"不同：**这是工具问题，不是信息问题** |
| `WAIVED` | 用户明确表示暂不处理。**≠ 已解决**，必须保留在报告里 |

`WAIVED` 与 `PASS` 严格区分 —— 这是原体系里 `PASS_WITH_WAIVER ≠ PASS` 的同一条纪律。

## 3. 审查门禁 R0–R6

> 原体系核心原则：**"门禁是阶段退出证据门，不是审批门。"**
> 我们照此执行：自查、记录、继续，**不新增等待点**；只有证据缺失时才停住依赖链。

| 门 | 依赖 | 通过判据 | 硬规则（越过就别下结论） |
|---|---|---|---|
| **R0 规格** | 器件手册 / 屏规格 / 电池曲线 | 关键电压、电流、温度范围齐全 | 缺关键规格 ⇒ 相关条目只能 `待确认` |
| **R1 原理拓扑** | R0 | §3A 电源/接口/保护项过一遍 | **R1 未过不审布局**（拓扑错，布局再好也没意义） |
| **R2 器件物料** | R1 | 设计值 = 绑定料号；位号唯一；UniqueId 唯一 | 错料/重号未处理 ⇒ 不出口"可打样" |
| **R3 连通性** | ENET 网表 | 网表产出 + 器件对账 + 单点网/悬空脚列清 | **网表拉不出 ⇒ 后续几何结论全部 `NOT RUN`** |
| **R4 图面几何** | R3 | `sch check` 跑完；`bridge-check` 交叉验证 | **检查器崩 ⇒ `NOT RUN`，绝不能当"0 问题"** |
| **R5 PCB** | R1 冻结 | DRC/DFM 逐条真伪分拣 | **R1 未冻结不审 PCB**；PCB 空板 ⇒ `NOT RUN` |
| **R6 交付** | R5 | BOM 身份、Gerber/钻孔/CPL、恢复演练 | **R6 未过不说"可打样/可量产"** |

**门禁结论只用于四档**：`PASS` / `PASS_WITH_WAIVER` / `BLOCKED` / `UNSUPPORTED`。
缺证据一律 `BLOCKED`，**不默认通过**。

## 4. 豁免规则

**不可豁免**（电工正确性的地基，任何理由都不行）：

- 电气 DRC / 原理图连通性
- 网表对账（器件数、单点网、悬空脚）
- PCB DRC
- 关键网络连通性证明
- 保存后重开仍存在（持久化）
- BOM 身份（设计值 ↔ 料号）

**可带理由豁免**：命名规范、图面整洁（重叠/零长线）、丝印、功能分区框、测试点、测试计划。

豁免必须落四项：**范围 + 理由 + 剩余风险 + 复验条件**，并在报告里写成
「`WAIVED`（用户 2026-10-29 决定暂不处理）—— 剩余风险：… ；条件：…」。

---

## 5. 反自欺清单（下结论前逐条过）

- 退出码 `0` **≠** 检查过；无报错 **≠** 没问题
- 器件数对上 **≠** 连接对
- 截图/渲染漂亮 **≠** 网表对
- 脚本自己打印 `OK` **≠** 真的落盘（必须回读）
- 检查器报的 **≠** 都是真的（`wire-contact` 一类必须交叉验证）
- 检查器没报 **≠** 就没问题（ENET 漏器件、屏蔽区、空返回都是"没报"）
- 单个数字好（布局评分 96、DRC 0）**≠** 电路正确
- 「用户说先不管」**≠** 「已修好」—— 记 `WAIVED`

## 6. 落地到报告

报告每条结论的格式：

```
### <问题>
- **状态**：`不满足` / `已验证` / `WAIVED` …
- **证据**：<网名 / 坐标 / 实测值 / 命令+日期>
- **判据**：<为什么这算问题 —— 手册限值、计算、比较对象>
- **建议**：<改法，按成本排序>
```

报告开头的"数据来源"行必须写清**五态各自的结果**：

```
数据来源：ENET 网表 ✅ / sch_parts ✅（已排除屏蔽区 7 件）/ connectivity ⚠ ENET 合成 /
         sch_check ❌ NOT RUN（非正交斜线，检查器崩）/ bridge-check ❌ NOT RUN
⇒ 本轮几何类结论全部 NOT RUN，仅连通性与器件级结论有效。
```
