## A. 连接与环境

- `curl /health` 返 **502 Bad Gateway** 但 bridge 明明活着 → 沙箱/CI 注入了 `http_proxy`，把 `127.0.0.1` 也代理走了。
  跑任何脚本前 `export no_proxy="127.0.0.1,localhost"`。
- `edaConnected:false` 一直不变 → 扩展自动重试约 5 次即停；bridge 重启或 EDA 先启动都会错过。
  先**长轮询** `/health`（数十秒）；仍不通请用户在扩展里点 **API Gateway → 重新连接**。
- 长流程跑到一半报 `EDA window "…" disconnected` → 扩展重连后 **`windowId` 变了**。
  重连会**丢未保存编辑** ⇒ **审查前务必确认工程已保存**；长审查中间也要留意连接是否重新建立。
- **读/写前都核对当前工程与当前文档**（用户可能同时开着别的工程，如云端原稿与本地副本）。

## B. ★★ 文字类图元"不落盘" —— 影响你读到的数据是否稳定

- `sch_PrimitiveText` 的增 / 删 / 改**会话内生效，关页签重开全回退**（`save()` 返 true 也没用）—— 文字类图元不落盘。
- ⇒ **审查开始前先确认设计已保存**；`save()` 是**异步**的，返 true 也可能只存了一部分（实测 81/163）。
- ⇒ 凡是涉及"文字 / 丝印内容"的结论，标注"以当前保存态为准"。

## C. 坐标 / 单位 / 符号（读几何最容易错的一块）

| 症状 | 根因 | 对策 |
|---|---|---|
| 整块内容出现在页面**另一侧**（镜像） | 页源 **y = −(API 传入 y)**；页源/PDF 的 y 是**正值(向下)**，API 读回是**负值(向上)** | 两侧统一符号；改完逐条比对坐标 |
| mil 去 Gerber 里搜坐标搜不到，误判"没铜" | Gerber 坐标是 **mm（4.6 小数）**，如 `X152400000` = 152.4mm = 6000mil | 换算后再搜 |
| polygon 长度是**奇数**、与预期不符 | `polygon` 是**裸数字与 `'L'` 标记混排** | **先滤出所有 number 再两两配对**，别按 `[i]/[i+1]` 跨步取 |
| 折返/平移后自交、净空算错 | 同一条线的点序可能是**降序** | 先归一化成升序再算 |
| 封装几何整体偏移 | 局部坐标转过来**又叠加了一次器件 `at` 偏移** | 局部坐标只做单位换算（×39.3701），**不再加偏移** |
| 从 PDF 抄的坐标总差一点 | PDF 的 bbox 是**行盒**不是墨迹 | 按基准图上的**墨迹**量；PDF 可能**多内容流重复**同一图元、且成对出现**退化零长段** ⇒ 去重 + 先滤零长段 |

**单位速记**：PCB = **mil**；原理图 = **0.01in(10mil)**；Gerber = **mm(4.6 小数)**；**1 in = 39.3701**。

## D. 读对象 / 当前文档（"读错文档"是脏数据之源）

- 写图元前必须**轮询到"当前文档 == 目标"**再动手；只 `sleep` 会写/读到上一个文档。
- 读 `getAll()` 抛 `Cannot read properties of undefined` → 多半是**读错文档**，**不代表"板坏了"**。
- 跨文档会**脏读**（出现坐标异常 / 超框的图元）⇒ 对账时这类单独报数，不计失败。
- **空壳封装**：器件落上了却读不到焊盘（`[]`）→ 该封装是"空壳"（中途失败留下的空文档）。
  判**封装真实引脚数**的权威方法是**逐个读封装源数焊盘**，不是看名字清单。

## E. API 可用性与字段（哪些读数 API 能信）

- **PCB 侧运行时坏掉 / 不存在**的接口（多为**写**接口，读时别指望对应"对象类型"存在）：
  `pcb_PrimitiveLine.create`、封装域 `pcb_PrimitiveString.create`、`pcb_PrimitivePour.create`、
  `pcb_PrimitiveRegion/Poured.create`、非正圆 `ELLIPSE`、`['POLYGON'/'NGON',…]` 焊盘。
  原理图侧 `Junction / Dot / NetPoint`、`getSvgFile / getPngFile` 运行时不存在。
- **读回字段名别猜**：走线是 `net / layer / polygon / lineWidth`；焊盘编号字段是 **`padNumber`**；
  `create` 返回对象的 id 在 **`.primitiveId`** 属性上（不是 `getPrimitiveId()` 方法）。
- **层号表**：`TOP=1 / BOTTOM=2 / SILK=3,4 / MASK=5,6 / PASTE=7,8 / OUTLINE=11 / MULTI=12`；
  **内层从 15 起**（`In1=15 / In2=16`…）。⚠ `getAllLayers()` 会列出全部 Inner，**别按列表顺序推层号**。
- **组件类型判据是「小写字符串」**：`getState_ComponentType()` 返回 `'part'`（普通器件）/ `'netflag'`（网络标签）/
  `'sheet'`（图纸）；而 `ESCH_PrimitiveComponentType` / `ESYS_NetlistType` 等全局枚举在 bridge 执行环境里是
  **`undefined`**。按 `=== 'COMPONENT'` 判等会**恒不成立**（踩过：region 导出误报"没有普通器件"）。
- **ENET 网表会漏器件**：`getNetlistFile` 的 `components` 以器件 **Unique ID** 为键，**UniqueId 为空的器件整条缺失**
  （典型：未转 PCB 的遗留占位）⇒ **器件数对账 / 重复位号检查要用 `sch_PrimitiveComponent.getAll()`**，别只信 ENET。
- **选区跨 `/execute` 请求不保持**：程序化 `doSelectPrimitives()` 的选区在下一次请求里读不到（用户手动框选的可读到）。

## F. ★★ 铺铜："看着有铜" ≠ 真有铜

- **`Pour`（覆铜框）只是定义域，本身不画铜**；`Poured` 无 API；`Region` 不进铜
  ⇒ 交付的 Gerber 里可能**一层平面都没有**（`G36/G37` 全 0）。
- **硬判据**：**每层 `G36` 计数 == 该层落下的填充环数**。
- ⚠ 平台"Copper Areas"统计**只数覆铜对象、不数实心填充** ⇒ 恒 0，**不能**当"有没有铜"的判据。
- 实心填充**只能表达"无孔单环"** ⇒ 带内孔的平面要化成"细缝连通"的无孔多边形；
  加净空只增顶点，`G36` 计数不变（验收要看**填充面积减少量 / 顶点数 / Gerber 文件长度**）。

## G. ★★★ 验收与对账（"假绿"合集）—— 审查结论的纠错地基

**核心两条硬规矩**（否则结论会系统性失真）：

1. **口径必须含"数量对账"**（实测条数 vs 期望条数，含"多余"这一侧）；删/改后**独立复核残留**。
2. **位置必须与外部基准量化对账**（原始 PDF 矢量 > 高分辨率基准图 > 用户截图）——
   **别拿"我们自己的记录"当期望值**（自证循环：实测框线错位上厘米、整页缺几十条，仍一路全绿）。

**其他判读陷阱**：

- **DRC / ERC 不能想当然当判据**：在**离线/本地模式**下，`pcb_Drc.check()` 可能**恒 false**、
  原理图 ERC 可能**恒返固定错误**、网表接口返 `undefined`（"假绿"）。
  ⚠️ **但本机 run-api-gateway + bridge 环境下实测 DRC 是能返回具体违规的**（曾拿到 PCB 4 条违规 + 原理图 PIN2PAD error）。
  ⇒ 结论：**DRC 结果必须实测确认、逐条真伪分拣**——既不全信，也不因"已知会假绿"就全不信；
  凡 DRC 报的，都**回原始数据核实**（网名 / 坐标 / 实测间距）。
- **页框是表格型符号**，自带一批文字 ⇒ 数原理图文字/器件时**别用绝对计数**（实测"自己 10 条文字读出 37 条"）。
  ★ 判页框看**符号 uuid**。
- **导线对账要三归一化**（否则刷一堆假差异）：丢**零长段**、丢**斜段**、
  **两端都落在期望端点上的"多出段"= 连接段**（不改连通性，单独报数、不计失败）。
  ★ 同一网名且端点相接的导线**会被平台自动合并成一条**，读回可能只给其中一段
  ⇒ 相接导线用"覆盖/连通"口径，别按"逐段精确匹配"。
- **过孔连通性**：过孔净空靠细缝相连时，盘心可能落在自己的净空腔里
  ⇒ 同层同网过孔"**盘(半径 D/2) 与平面环相交**"也应判为连通。
- **连通性判定必须做真正的"点在多边形内"**，禁止包围盒近似（会**假连通**）；
  导体只有 **走线 / 焊盘 / 过孔 / 平面填充**。
- **诊断"某处能不能改/能不能放"五步法**：① 先从现有版图**反推本板真实 DRC 间距**（别猜，别拿铺铜净空当 DRC 间距）；
  ② 盘径全扫找真瓶颈层；③ 逐对象列"谁挡路、差多少"；④ 做**单删灵敏度**（真障碍通常只有 1~2 个）。
