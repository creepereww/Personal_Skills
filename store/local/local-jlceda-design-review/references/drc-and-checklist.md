# DRC 判读表 · 质量门 · 规范（审查用提炼）

> **来源**：SkillHub skill `pcb-design-assistant`（MIT 许可）的 SKILL.md 提炼。
> 原文面向"画完即投产"的动手设计；这里**只取"判读 / 清单 / 规范"部分，改造为只读审查视角**，去掉动手步骤。
>
> 用法：审查 PCB/原理图时，用 §1 翻译 DRC 条目、用 §3 质量门过检查项、用 §4 查网标规范符合性、用 §5 判"假元件"。

---

## 1. DRC 报错翻译表

把工程黑话翻成"这条到底在说什么 + 往哪个方向改"（审查报告里可直接引用作建议）：

| DRC 报错 | 含义 | 修复方向 |
|:---------|:-----|:---------|
| `Net has no driving pin` | 网络只有输入、无驱动源 | 源端加驱动元件（电源/输出脚），或检查是否漏放元件 |
| `Unconnected pin` | 引脚未连到任何网络 | 判断引脚功能；若 NC 则标 `NC`，否则连到正确网络 |
| `Net name collision` | 同名网络电气不连通 | 合并或重命名；避免 `GND` 被拆成多段（**跨页同名网必须真连通**） |
| `Clearance violation` | 走线间距不足 | 调线宽/间距规则或重布；高密度区考虑改 4 层板 |
| `Silk over pad` | 丝印盖焊盘 | 移丝印或缩小丝印字体 |
| `Hole too small` | 过孔孔径小于工艺下限 | 嘉立创工艺下限约 **0.2mm 孔 / 0.4mm 盘**，按下限上调 |

> ⚠ 本表是"报错→含义"的对照，**不代表该报错一定是真违规**——见 `pitfalls.md` §G：DRC 真伪必须回原始数据核实
> （尤其间距类，实测常出现"实测值已超要求却仍报错"的假红）。

## 2. 修复优先级决策树（给"建议"排序用）

```
DRC 报错
 ├─ 电气类（net / driving pin / collision）→ 先查原理图，再查 PCB 网络表 ★ 优先
 ├─ 间距类（clearance / width）           → 查规则设置 → 调规则或改层数
 └─ 制造类（silk / hole / size）           → 查工艺下限表 → 调元件或规则
```

**电气类错误常引发连锁：修一条往往消除多条报错** ⇒ 报告里把电气类排在最前。

## 3. 质量门 → 审查检查项（由"写入前自检"改造为"审查时核对"）

- [ ] **当前文档/页面正确激活**（读对文档，否则数据是脏的）
- [ ] **关键器件有真实料号与封装**（不是"纯符号元件"——无封装、无库存的占位件）
- [ ] 抽样走线用 `getState_Net()` 验证**关键网标真实存在**（别只信坐标重建）
- [ ] **电源轨与地已标注**（见 §4 命名规范）
- [ ] **IC 电源引脚附近有去耦电容**（典型 100nF；缺了要报）
- [ ] **连接器暴露的网标已标注**
- [ ] 跨页网络用**相同网名** + 页间连接器/全局网标（抽查跨页连通性）

## 4. 网标命名规范（审查"规范符合性"时对照）

| 信号类型 | 命名模式 | 示例 |
|:---------|:---------|:-----|
| 电源轨 | `V<电压>` 或 `<网络名>_P<电压>` | `V3V3`、`VBAT_P5V` |
| 地 | `GND` 或 `<功能>_GND`（区分模拟/数字地时） | `GND`、`AGND`、`DGND` |
| 数字信号 | `<模块>_<功能>` | `MCU_UART0_TX`、`SENS_SDA` |
| 模拟信号 | `<功能>_A` 后缀 | `VSENSE_A`、`ISENSE_A` |
| 差分对 | `_P` / `_N` 成对命名 | `USB_DP` / `USB_DN` |

> 审查时的红旗：成堆的自动名 `$1Nxxx`、`GND` 被拆成多段、电源轨没有统一前缀。

## 5. "真元件"判据 / 选件优先级（审查"假元件 / 无料号"）

按优先级降序；**禁止纯符号元件**（无封装、无库存的占位件）：

| 优先级 | 来源 | 标注要求 | 适用场景 |
|:-------|:-----|:---------|:---------|
| P0 | JLCPCB 基础/扩展贴片库 | 元件编号、库存数、替代料编号 | 直连下单、小批量打样 |
| P1 | EasyEDA 官方元件库（有真实封装） | 元件编号、数据手册链接 | 原型验证 |
| P2 | 用户私有库 / 项目已用元件 | 复用既有编号与值 | 维护旧板 |
| P3 | 自建符号+封装 | 必须标注数据手册与 footprint 来源 | 库内确实无合适元件 |

**每个选定元件应能报出**：`[元件编号] | [封装] | [库存数] | [替代料] | [数据手册来源]`。
审查时可据此判：**有多少器件填了立创编号**、有没有"假元件"、有没有缺库存风险。

## 6. 交付物自洽（可制造性审查用）

| 交付物 | 内容 |
|:-------|:-----|
| BOM | 元件编号、值、封装、数量、**库存**、替代料 |
| 坐标文件（CPL） | 元件位号、X/Y、旋转角、层面 |
| Gerber 包 | 各层 Gerber + 钻孔文件 |
| 装配图 | 顶层/底层丝印 + 位号 |
| 设计说明 | 假设、风险、关键参数、电源树 |

> 审查时看：**必需层是否齐全**、BOM 是否与原理图器件一致、测试点/跳线是否漏进 BOM。

## 7. 故障排查（与审查相关的几条）

| 现象 | 排查路径 |
|:-----|:---------|
| 桥接无法连接 EasyEDA | EDA 是否运行 → 桥接端口占用 → 重启桥接脚本（另见 `pitfalls.md` §A） |
| 读数据返回空 | 确认**活动页面/文档正确** → 对象是否在选择集内 → 先按 id 精确取 |
| 元件读不到网标 | 引脚是否对齐网格 → 用 `wire` 而非 `line` 连接 → `getState_Net()` 验证 |
| DRC 跑不出结果 | 规则文件是否加载 → PCB 是否已生成（非空）→ 层叠设置（见 `pitfalls.md` §G） |
| Gerber 缺层 | 层映射配置 → 各层是否有图元 → 核对层名 |
