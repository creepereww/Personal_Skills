# 脚本优先：能固化的操作就别每次重想

**一句话**：skill 讲"怎么做才不跑偏"，脚本保证"每次都做对"。
凡是确定性的、会重复的操作，写成脚本；动手前先找脚本，别重新想一遍。

## 一、什么该转成脚本

**该转**：

- 这是**第二次**做（第一次手工摸索没问题，第二次就该固化了）
- 步骤**确定**：给定输入，输出唯一或可判定
- **多步骤、有顺序、容易漏**的手工活
- **需要校验**的 —— 脚本能 `assert`，而模型只会"觉得应该没错"
- 同一套参数**反复**做的查询/生成/转换

**不该转**：

- 一次性探索（每次目标都不同）
- 需要**判断和取舍**的（那是模型的活，脚本只会把判断写死）
- 只是跑一条命令（直接跑，包一层脚本反而绕）

**灰色地带的快速判据**：同一件事你在**同一个会话里说了两遍** —— 该转了。

**⚠️ "划算"要算频率** —— 转脚本**不一定**让 skill 变短：

| 账 | 谁付 |
|---|---|
| skill 里的"可用脚本"表（几行） | **每轮触发都付**（常驻上下文） |
| 省掉的"每次贴正则/手敲 grep/组装判断" | **只在执行时省** |

所以判据是**这活多久做一次**：

- **经常做**（改完就要跑那种）→ 转，哪怕 skill 多几行也值
- **很少做** → 别转，skill 里留步骤就行（多写的脚本没人用）

刚踩过：给两个 skill 加脚本索引，行数不降反升（+5/+10）——因为索引表本身要占篇幅。
但那两处是"每次改完都要跑"，所以值。

## 二、脚本怎么写（本机约定）

**放哪、叫什么**

- 仓库级通用脚本 → `~/.skills/scripts/`
- skill 专属脚本 → 该 skill 目录下的 `scripts/`
- 头部注释写清三件事：**干什么、怎么用、有什么前置**

**必须做到**

1. **幂等** —— 重复跑结果一致（所以用"标记块替换"而不是无脑追加）
2. **失败要响** —— 静默成功是大忌（吃过亏：`str.replace` 没匹配时静默无操作，漏改一整轮）
3. **改完回读验证** —— 不信脚本自己的成功输出，要读回来看
4. **不用非零 exit code 表示"有问题"** —— 宿主工具遇到非零退出码会**丢掉 stdout**，反而看不到结果。失败信息写进输出正文
5. **路径用正斜杠**，别用反斜杠 —— bash 里 `\U` `\c` 会被当转义符吃掉
6. **改动用户文件前先备份**，并告诉用户备份在哪

**本机踩过的坑**（细节见 `local-wgc-machine` 与 `local-workbuddy-quirks`）

- `ConvertFrom-Json` 读 UTF-8 会乱码 → 改用 `python -c "import json; ..."`
- pwsh 工具的输出拿不回来 → 结论写文件，再用 Read 读回
- 删除走 safe-delete，`-Force` 覆盖旧目录会失败 → 先 `mv` 到备份再写新的
- 正则不可靠（`re.subn` 曾返回 0 次替换却不报错）→ 能用逐行替换就别用正则

## 三、怎么保证"有脚本就直接跑"

**写 skill 的人的义务**：

1. **skill 里显式列出配套脚本** —— 该有一节「可用脚本」，写清路径 + 用途 + 关键参数
2. **步骤里写"跑哪个脚本"**，不要重述脚本内部的逻辑 —— 重述既占上下文，还会和脚本漂移
3. 脚本改了要**同步改 skill 里的说明**

**⚠️ skill 里列脚本要极简** —— 一行"路径 + 什么时候跑"就够，**详细用法交给脚本自己的 `--help`**。
把参数表抄进 skill 会让 skill 变长，而且脚本一改参数就对不上了（刚踩过：给两个 skill 加脚本索引，
结果行数不降反升）。

**执行时的一条硬规则**：

> 动手做任何**有确定步骤**的事之前，**先看有没有现成脚本**：
> `ls ~/.skills/scripts/` 和该 skill 目录下的 `scripts/`。
>
> - **有** → 直接用（可以调参数，别顺手改脚本）
> - **没有，但这活会重复** → 顺手写一个，并登记到 skill 的「可用脚本」里
> - **没有，且只做这一次** → 直接做，别为了"规范"硬造脚本

## 五、脚本和 skill 怎么分工

| 内容 | 放哪 |
|---|---|
| 确定性的步骤、可判定的转换、校验 | **脚本** |
| 判断标准、取舍原则、什么情况别这么做、踩过的坑 | **skill** |
| 两者都有 | skill 里写"为什么 + 什么时候用"，脚本里写"怎么做" |

**一个信号**：如果 skill 里出现了一长串"先做 A，再做 B，最后 C"且每次完全一样 ——
**那段该变成脚本**，skill 里只留一行"跑 X 脚本"。
