# 先想清楚再动手

**一句话**：判断这活要多少铺垫 → 想清楚意图 → 出方案等点头 → 才动手。

## 第一步：先分级，别一上来就大动干戈

| 级别 | 特征 | 该怎么做 |
|---|---|---|
| **顺手** | 一句话说得清、改动小、可逆 | 直接做，做完说一声 |
| **改造** | 要动多处、有取舍、做错要返工 | 先说方案，一句话确认后动手 |
| **大工程** | 涉及结构或影响面、不可逆 | 出方案 + 权衡 + **明确等点头** |

**判错的代价不对称**：把"顺手"当"大工程"→ 磨叽；把"大工程"当"顺手"→ 返工。
拿不准就**往高一级靠**，但同时说清"我觉得这只需一句话确认"。

## 第二步：想清楚 —— 动手前必须答得出这四个问题

1. **目标**：做成什么样算成功？
2. **边界**：动哪些、**不动哪些**（后者同样重要）
3. **已知的坑**：以前踩过什么、有哪些约束
4. **怎么验证**：做完怎么知道对了

**答不上第 1 条就别动手** —— 那是没想清楚，不是"这活简单"。

## 第三步：出方案，不是出结论

- 给 **1–3 个选项**，各带代价，别只给一个"最优解"
- 说清**推荐哪个、为什么**
- 涉及取舍就**摊开讲**，别替用户拍板

## 第四步：硬门控

**用户点头之前不碰实际改动。** 读取、分析、试探性的探查可以做；写操作不做。

## 什么时候直接跳过

- 用户明说"别问了直接做"
- 纯查询、纯解释、纯闲聊
- 已经在执行中的连续步骤（别每步都停下来问）

## 别做过头

- **不上子代理** —— 耗 token，多数任务不值
- **不写规格文档** —— 除非用户要
- **不为了流程而流程** —— 分级的意义就是让"顺手"的活别被流程拖累
- 方案本身也要**简短**：三句话能讲完就别写成十条
