# 单文件 HTML 知识库维护

适用于 `装修知识大全.html` 这类单文件知识库：内嵌 CSS/JS/base64 图片、章节为
`<section class="chapter" id="cXX">`、
折叠块为 `<details class="item-fold|sec-fold|point-group|vc-details|fig-gallery">` + `<summary>`、
提醒块为 `<div class="callout warn|tip|info|rec-box|err">` + `<div class="ctitle">`、
推荐表为 `<table class="ctable rec-tbl">`。

> **推荐表的「核验」列已删**，末列现为 `预算（参考）`；残留 `class="rv"` 是历史遗留，新增表别再套。

> **动手前先看文档同目录的 `_文档实况.md`** —— 章节顺序、各类计数、体积这些**会变**的状态放在那儿，
> 不写进本 skill（skill 只放方法，不放快照）。改完文档记得回去更新它。

**四个场景，先判断用户要干什么**：

| 场景 | 信号 |
|---|---|
| ① 增量接入 | 用户分批粘贴内容，要求「评审 + 精简 + 放进对应章节」 |
| ② 插入新章节 | 概念独立成章、新增章节导致后续 cXX 全部后移 |
| ③ 批量结构重构 | 章节搬家/对调、批量增删折叠块、批量改标题、修排版错乱、全文体检 |
| ④ 推荐表批量编辑 | 给每章推荐表统一加列（预算/价格）、按行填值 |

**所有场景的公共纪律**（先读这五条）：

1. **改前备份**：`cp 文件.html 文件.备份-YYYYMMDD-HHMMSS.html`；备份文件永远不要被脚本自身覆盖。
2. **用 Python 脚本改，不用 Edit 工具做大块插入**：内容长时易出错且难回滚。
3. **每步 assert 唯一性**：`assert html.count(anchor) == 1`；批量计数与预期不符就报错，绝不静默通过。
   `str.replace` 不匹配时**静默无操作**（曾因 `<li>` 间 6 空格缩进漏改一整轮）。
4. **改后回读校验**：`assert new in html` 或对比 count 前后差值。
5. **收尾跑校验三件套**（见文末）。

## 可用脚本（优先跑，别手工重做）

详细参数用 `--help` 看，这里只记"什么时候该跑它"：

| 脚本 | 什么时候跑 |
|---|---|
| `scripts/probe_kb.py` | **动手前** —— 结构速探：章节 id→行号、details/callout 计数、表格数、new-tag 风格 |
| `scripts/scan_kb.py` | 改完收尾、排查"排版错乱" —— 8 类结构问题一次体检 |
| `scripts/check_rec_tbl.py` | 推荐表批量改完 —— 计数核对（表头 / 该列单元格 vs 数据行 / 章节注释） |
| `scripts/insert_chapter.py` | 要插章时 —— 在指定章后插入并整体重编号（**先 `--dry-run` 看**，它会自动备份、防重跑） |

路径可用 bash 的 `/c/...`，脚本自己转。
## 场景一：增量接入（评审 → 精简 → 写入）

### 工作流

1. **摸清结构**（首次）：跑 `python scripts/probe_kb.py <html>` —— 一次给出章节 id→行号、callout 变体、new-tag 风格、表格数。
2. **检索去重**（每批必做）：`grep -c '<关键词>'` 看内容是否已存在；
   已存在则新章节做深度展开 + 旧条目加交叉引用徽章，不重复堆砌。
3. **联网核实关键数据**：只核实影响结论的硬数据（国标号、性能分级、壁厚、功耗、价格区间、平台能力），
   纯经验描述不核实。来源分流：官方标准/厂商文档 → 直接采用；多个独立测评一致 → 采用；
   营销文/单一实测 → 文中标注「厂商标称」「第三方实测，仅作趋势参考」；无源对比数字（"强 N 倍"）→ 删或改定性。
4. **评审并列问题清单**（用户习惯的格式）：
   `✅ 判定正确予以保留（含核实依据）` / `⚠️ 发现问题已修正（N 处，表格：原文问题/处理）` /
   `🔴 关键遗漏已补充` / `✂️ 已删除（重复粘贴、看图笔记、对话式追问）`。
   重点排查：自相矛盾、口径不统一、类别不一致、单位混乱（W vs W/天）、无来源数字、AI 助手残留追问。
5. **写入**（Python + 唯一锚点）：

```python
import io
P = r'绝对路径'
s = io.open(P, encoding='utf-8').read()
anchor = '<唯一锚点字符串>'   # 插某节前 → 用该节 <h3 class="sub">xxx 开头；追加章末 → 用下一章 <section id="cXX"
assert s.count(anchor) == 1, s.count(anchor)
s = s.replace(anchor, BLOCK + anchor, 1)
io.open(P, 'w', encoding='utf-8').write(s)
```

6. **校验**：正则栈校验标签闭合（跳过 void 元素），要求 `unclosed: [] errors: 0`；
   再核对章节边界（`grep -n 'id="c15"\|id="c16"'`）确认没泄漏到下一章。
7. **更新工作区记忆**：本批归属章节 + 新增小节清单；**核实过的硬数据结论（下批复用不用重搜）**；修正的问题；验证结果。

### 坑位

- **重复粘贴**：用户常把同一段贴两遍，写入前先通读去重。
- **AI 助手残留**：原文末尾常有「你家现在是在装修还是…？」这类对话式追问，必须剔除。
- **看图笔记**：「先看图…盯这两个细节」是观感描述不是知识条目，只提炼结论。
- **美元口径**：外文换算的美元金额改人民币并注明估算依据。
- 文件含 base64 内嵌图时体积涨得快，每批记录体积变化。

## 场景二：插入新章节并重编号

### 工作流

1. **先与用户确认编号方案**：
   - 方案 A：整体后移（插为 cN，原 cN–cM 变 cN+1–cM+1）
   - 方案 B：逻辑位置插入但保持原编号（追加为 cM+1）
2. **备份**（公共纪律 1）。
3. **Python 脚本执行**（可用 `scripts/add_water_chapter_renumber.py` 作参考实现）：
   - `old_id → new_id` 映射覆盖：`<section class="chapter" id="cXX">`、`data-ch="cXX"`、`href="#cXX"`
   - 更新可见文本中的 `cXX` 引用（跳过 `<script>`/`<style>`/标签属性）
   - `<a href="#cXX">` 链接文本与 href 目标对齐
   - 在正确位置插入新章 `<section class="chapter" id="cN">`
   - 修正所有 `<h2>XX 标题</h2>` 与 section id 数字一致
   - 从原位置删除被抽出的卡片（如有）
   - 更新顶部导航、侧边目录、对应 part 副标题、静态章节统计
4. **校验**：标签平衡 / 章节顺序唯一 / 失效锚点 / `node --check` JS 语法。
5. **更新工作区记忆**：需求、要点、校验结果、脚本路径、备份文件名。

### 坑位

- 文本引用正则 `\bc(0?\d{1,2})\b` 会匹配 `c6`/`c06`/`c25`；替换后保持 `cN` 无前导零风格。
- 新章内容用户未提供时，可基于原卡片搭骨架（系统链路、分类子项、预留/选购提示），不硬编未验证数据。
- **章节 id 重排用占位符法两级替换**，避免 `c12→c05` 与 `c05→c06` 级联错乱。
- 提取章节块须含 `<section>…</section>` 外壳，只取内层会丢 section 标签。

## 场景三：批量结构重构与全文体检

### 九步流水线（顺序不可省）

1. 备份（公共纪律 1）。
2. **打印原文 repr 再替换**：`print(repr(html[i:i+200]))`。匹配不上 90% 是换行/缩进/全角字符；
   `h3` 闭合常是 `\n</h3>`（换行在闭合标签**前**）。
3. 每步 assert（公共纪律 3）。
4. 替换后回读（公共纪律 4）。
5. **校验三件套**（见文末）。
6. **结构专项扫描**（章节搬动/新增后必做）：空 callout、空 ul/ol、`<summary>` 内混入块级内容、
   `</summary>` 后重复标题、断链与章号不一致。正则见下。
7. **新增表格必须带 `<colgroup>` 列宽**，否则浏览器自动布局把长文本列压成一字一行。
8. **小节插在折叠块「之前」时，锚点取 `<details>` 标签本身**，绝不能取 summary 内文本
   （曾把整节插进 `<summary>`，被 `display:flex` 压成竖排）。
9. **向某章新增内容前先 grep 该章现有卡片**，同名词合并而非并存
   （「骑马抽」曾同时存在于表格行和卡片，且口径打架）。
10. **删嵌套块后必须闭环验证**：重跑重复检测，确认「重复段落 / 重复列表项 = 0 组」，
    而不是只看脚本自己打印的"已删除 N 条"。

## 统计与审计纪律（审计类任务必读）

**统计 HTML 元素一律走 HTMLParser 标签栈，禁止用正则**：正则 `<table class="[^"]*"` 匹配不到**无 class 属性**的表（`<div class="ctable"><table>` 写法），会静默少算 —— 本项目因此把「缺 colgroup 139」报成 137。是否被 `.table-wrap` 包裹必须靠**祖先链**判断，不能靠字符串邻近：

```python
class T(HTMLParser):                      # 标签栈：stack 存祖先 class
    def handle_starttag(s,t,a):
        if t=='table': s.tables.append({'anc':[x[1] for x in s.stack]})
        if t not in VOID: s.stack.append((t,dict(a).get('class','')))
    # handle_endtag 做栈配对；「未被包裹」= anc 里没有 table-wrap
```

1. **同一现象要按不同写法分别搜**：m / mm / cm / 米（「1.8m」vs「1.8米」），单一正则会漏 2 处。
2. **凭印象报数 = 报错数**。「未包 table-wrap 8 张」是没实测的印象值，实测 3 张。没跑就别写数字。
3. **`validate_html.py` 对未闭合 `<div>` 不敏感**（标签总量能对上但嵌套错位时漏报）。查嵌套必须另跑严格配对栈；本项目用它查出 c22 内一处 `.table-wrap` 的 div 未闭合、连带吞掉外层 section。
4. **外部给的审计数字也要复算**，别因「对方是审核方」就采信。实测双方各错一半（一方把 139 报成 137、3 张报成 8 张；另一方自纠 thead 28→29、caption 152→153）。双向规则：别只信脚本自己打印的成功信息。

## DOM 实测纪律（跑 jsdom 前必读，踩了三次）

1. **`new JSDOM(html)` 默认不执行页面 JS**：不加 `runScripts:'dangerously'`，页面 `<script>` 根本不跑 —— 据此误判过「展开按钮无效」，加上后实测 23→143→0 正常。**报「功能失效」前先确认探针开了 `runScripts`。**
2. **统计 DOM 数量的脚本必须挂 `DOMContentLoaded`**：主 `<script>` 在文档中部，末尾章节的元素在它之后，同步统计首屏数字长期偏小（callout 同步只数到 177、实际 181）。修法是在原 IIFE 内注册 `DOMContentLoaded` 重算 —— `setStat` 这类函数是闭包内的，外部调不到。
3. **判断「是否被某容器包裹」必须查祖先链**：用 `h[max(0,pos-90):pos]` 找类名会误报（误报 28 张表未包裹，真相是全包裹）。
4. **给悬空类名补样式前先量列位与内容语义**：`.rn` 共 1482 处，1023 处在非首列、内容是点位表类别标签（"强电"/"弱电"）。照同族 `.rb` 补 `color:var(--accent-dark)` 会让整片文字变蓝 ＝ 制造视觉噪音 → 只补 `font-weight:600` 不加色。**用户明确「视觉噪音是可读性的头号敌人」**。
5. **数 `details` 必须先说清「源码口径」还是「实载口径」，两者必然不等**：源码 135 个，jsdom 实载 143 —— 主 `<script>` 的 `wrap()` 会给行数 >12 的 `.table-wrap` 大表和每个 `.rec-box` 自动套折叠块，**是既有设计不是冗余，别「清理」**。任何「源码 grep vs 实载 querySelectorAll」对不上时，先找 JS 里的 `createElement`/`appendChild`。
6. **探针报的错先用改前备份对照再判是否回归**：jsdom 恒定报 1 条 `link.scrollIntoView is not a function`（它没实现该 API，浏览器里正常）。方法：`node 探针.js 改前备份.html` 与 `改后.html` 各跑一次，错误数与文案一致即可排除。**看到红色就以为自己改坏，是最浪费一轮的误判。**

## 跨章口径收敛的做法（同一现象在多章给不同数值时）

先把**所有**相关行连同所在章节抓出来聚类，再决定改哪几处。三个反复出现的形态：

| 形态 | 症状 | 改法 |
|---|---|---|
| 单值 vs 区间 | 一章写「0.8MPa」，另一章写「0.8–1.0MPa」 | 统一为区间，注上常用值 |
| 多套判定标准混用 | 一章引JGJ/T，另一章引GB，另一章用行业流传的经验值 | 收敛成「规范强制 + 严于规范的通行做法」两层，**分别标注** |
| **同章自相矛盾** | 同一章里行 N 说「必须配三件套」，行 M 说「不必加」 | 最容易漏，因跨章扫描看不出；**必须单开一个「同章一致性」扫描** |

- **组数别照抄**。审计方常写「共 13 组需收敛」，逐处勘察后真有冲突的可能只 5 组，另几组实测全文一致（防水上翻 7 处全一致、某项全文仅 1 处、占比合计 100.5% 自洽）。**别为了凑满组数去改没冲突的地方——那是制造无谓diff，还会让审核方多一轮核对。**
- **严于规范的通行做法要显式标注**（如「地砖中心空鼓即使在限值内也返工」是行业做法，非条文要求），别让读者当国标。
- 二手来源且**条号自相矛盾**的标准条款**不写进正文**（例：某条二手页面一处说 6.2.1、一处说 6.2.8）——按「引用标准条款的纪律」处理。
- 改完用正则做**残留扫描**（旧口径串全文 0 命中）＋ **内链一致性扫描**（链文本里的 `cXX` 必须等于 href 的 `#cXX`），才算收尾。

## 零行号漂移改法（对方按行号引用时必用）

审计/协作方常按「行N」引用问题位置。**此时任何增删行都会让对方的引用全部错位。** 做法：

- 改动一律用**同行内追加**，绝不新起一行：
  - 补 CSS 规则 → 压成单行接在已有规则后：`.a{…}  .b{…}  .c{…}`
  - 补闭合标签 → 贴在原标签同一行：`</table>` → `</table></div>`
  - 补DOM 节点 → 接在容器的开标签后：`<aside id="toc">` → `<aside id="toc"><div>…</div>`
- 在替换函数里断言换行数不变，不变就报错：

```python
def rep(old, new, expect, tag):
    assert h.count(old) == expect, f'[{tag}] 期望 {expect}，实际 {h.count(old)}'
    assert new.count('\n') == old.count('\n'), f'[{tag}] 会导致行号漂移'
    h = h.replace(old, new)
```

- 注：`new.replace(old,'')` 这种写法判断不了「净增换行」（新旧仅差少量字符时不成立），**必须直接比 `count('\n')`**。

## 引用标准条款的纪律（涉数值必读）

**判一条国标/行标数值对错，必须先拿到逐字原文**（条款号 + 原文表述 + 出处）。拿不到原文只能写「未核实／存疑」，**绝不能写「查无条文、建议删」**。
- 典型翻车：审计意见判「GB/T 8478-2020 的内门 2.0/内窗 1.4 疑似杜撰、建议删」——实际 5.1.2.1.2 条逐字规定「外门≥2.2、内门≥2.0、外窗≥1.8、内窗≥1.4mm」，照它动手会删掉本来正确的国标值。同类：「JG/T 298 无柔韧型 R 型」也是错的，Y/R/N 三型与 >0.30/>0.40/>0.50 与文档一字不差。
- **区分「规范强制」与「通行做法/图集值」**：
  - 属**地方规程/图集值**、不可写成 GB 强制的例子：轻钢龙骨吊顶「主龙骨 900–1200、副龙骨 400、横撑 600」——出处是上海市 DB31/T 1533《轻钢龙骨石膏板隔墙、吊顶应用技术规程》4.3.1，不是国标。
  - **检索不到条款 ≠ 该做法错**，往往只是「规范不管这件事」。例：「排水出墙角度 45°/90°」在 GB 50015-2019 查无此条（该标准只管水封，4.3.10/4.3.11 强制条文：水封深度≥50mm、严禁活动机械活瓣替代水封），所以角度属施工通行做法。改法是**删掉错误归因**（返臭取决于水封与密封，不是角度）、引水封条款，不引角度。
- **已有正确值不要动，只补口径说明**。例：壁厚四档一字不改，只补 2020 版把「最小实测壁厚」改为「公称壁厚 + 尺寸偏差精度等级」。
- 第三方标准解读页可作补充但**必须标注是二手转录**；openstd.samr.gov.cn 优先。

## 删除内容的安全做法（血泪教训）

**删嵌套 HTML 块绝对不要用跨块正则。** 曾用
`<div class="callout warn">….*?</div>\s*</div>` 删一个提醒块，
非贪婪匹配**吃掉了紧随其后的另一个 callout**，产出游离 `</details>`、标签失衡。
正确做法二选一：

```python
# A) 同级简单标签：str.find 精确定位，先核对内容再删
u1 = s.find('<ul>', k); u2 = s.find('</ul>', u1) + 5
seg = s[u1:u2]; assert seg.count('<li') == 5

# B) 任意嵌套：div 深度配对求块尾
def match_div(s, start):
    depth = 0; i = start
    pat = re.compile(r'<div\b[^>]*>|</div>')
    while True:
        m = pat.search(s, i)
        if not m: return -1
        depth += -1 if m.group(0) == '</div>' else 1
        if depth == 0 and m.group(0) == '</div>': return m.end()
        i = m.end()
```

**删之前必须证明"保留的那份是完整的"**：定位到重复项后，先断言另一处确实覆盖了全部条目，
再删。**校验不过立即回滚**（从带时间戳备份恢复，重跑已验证安全的脚本），不要在坏状态上继续叠加修改。

## 「丢信息」的判定标准（用户明确，勿再搞错）
> 「丢信息不是说要一字不差，而是**信息基本不变为主，可以改写内容**。」

| 情形 | 算不算丢 |
|---|---|
| 改写措辞、把一段话拆到不同列、合并两处同类表述、补充更精确的年限/数字 | ✅ **不算** |
| 某个事实/属性整体消失（如框架表丢了「适合：北欧/日式」、删行时丢了定义） | ❌ **算丢** |

**断言要查「信息点」，不要查「原句」**：

```python
# ✗ 原句型：合法改写就假报警（本项目曾连报 3 次）
assert '有娃有宠、怕脏、懒人' in TXT
# ✓ 信息点型：只确认要点都在
for pt in ['有娃有宠', '怕脏', '懒人']:
    assert pt in TXT
```
同时**别用计数型断言**（如 `len(rows) == 7`）：含 rowspan 的表上正则不稳，计数会误报；改成检查具体项。

**真·逐字相等**只适用于「移动/重排」类改动（内容一字不动），此时相等能证明没复制、没丢。

## 信息零丢失验证（任何内容改动都要做，用户明确要求）

改 HTML 前先存全文可见文本，改完逐字对比：

```python
def text_of(x):
    x = re.sub(r'<(script|style)[^>]*>.*?</\1>', ' ', x, flags=re.S)
    return re.sub(r'\s+', '', re.sub(r'<[^>]+>', '', x))
TXT_BEFORE = text_of(s)
# ... 改动 ...
assert text_of(s) == TXT_BEFORE        # 移动/重排类：必须完全相等
```

- **移动、重排、改标签类**改动 → 必须**逐字相等**，差一点就是内容复制/丢失。
- **删除类**改动 → 额外断言"被删内容已在别处存在"或"本就无信息量"。
- 这道检查**成本极低、价值极高**：靠它连续拦下两次「只复制未删除」的 bug（一次让内容翻倍、一次让封阳台窗那组 386 字重复出现），避免坏版本交付。

## 块嵌套会让「紧邻判断」失效

用 `s[前块结束 : 后块开始].strip() == ''` 判断两个块是否紧邻时，
**若存在嵌套，前块结束位置 > 后块开始位置，反向切片返回空串 → 误判为紧邻**，
随后按 `s[:a] + X + s[b:]` 插入就会把整段内容复制一遍（本项目实测多出 370 字）。
必须加守卫：

```python
pairs = [(a, b) for a, b in raw if a < b]     # 排除嵌套
nested = len(raw) - len(pairs)                # 单独统计嵌套数，别默默吞掉
```

本文档已知有 **1 处 callout 嵌套**（warn 内套 tip「✅ 四步封死渗水通道」），待查是否有意为之。

## 分析已有内容时的两个陷阱

1. **别用固定窗口截取元素文本**。用 `blk[m.end():m.end()+150]` 打印每个 `<p>` 的"开头 150 字"，
   会让**每段都显示出下一段的开头**，看起来像"段落被逐句切碎"的假象。
   正确做法是按元素边界切片取完整内容。教训来源：我据此误判 c12「碎片化」，回读原始 HTML 证实结构完全正常。
2. **CSS 规则归属不能只靠正则推断**。`.ctable td:nth-child(3){white-space:nowrap}` 静态看着像在 @media 内，
   jsdom 实测是全局生效；而 `td:nth-child(n+5){display:none}` 静态看着像全局泄漏，**实测证伪**。
   涉及 display/white-space 等关键样式，**用 jsdom `getComputedStyle` 实测**，别猜。
   （注：jsdom 不解析 CSS 变量 `var()`，涉及 var 的属性读不出真值，只能验非 var 属性。）

## 场景四：推荐表批量加列 / 填值

### 目标表判定（不要误伤对比表）

满足任一即目标：① class 含 `ctable rec-tbl`；② 表头文本含 `推荐型号`（覆盖 class 仅为 `ctable` 的表）。
排除：「材料价/对比」表（class 仅 `ctable`、无推荐型号，本身已有单价，勿加列）。

### 核心规则

1. **插列保留闭合标签**：`re.sub(r'(</th>)\s*</tr>', r'\1<th>新列</th></tr>', hr)`、
   `re.sub(r'(</td>)\s*</tr>', r'\1<td class="x">值</td></tr>', row)`。
   绝不能整体替换 `</td></tr>`，否则吞掉末列 `</td>`，新列和最后一列合并。
2. **关键词匹配只用第一列（材料/品类名）**，不用整行 —— 「选用说明」列常提及多种材料，
   整行匹配会误命中（`防水涂料` 含「涂料」→误判乳胶漆；`淋浴隔断` 含「验收」→误判验收项）。
3. **防关键词碰撞**（具体品类名优先于宽泛词；品牌名不做触发词；宽泛词加负向预查）：

| 裸词会误命中 | 改用 |
|---|---|
| `砖` → 瓷砖胶 | `红砖\|砌块\|烧结普通砖\|砖块` |
| `博世`/`西门子` → 洗碗机 | 只留 `洗碗机`（去掉品牌名） |
| `激光` → 测距仪/水平仪 | `测距仪\|水平仪` |
| `涂料` → 乳胶漆 | `乳胶漆\|墙漆`（去掉 `涂料`） |
| `网线` → 全屋WiFi（无网线老房） | `网线(?!老房)` |
| `面板` → 饰面板 | `面板系列`（具体词） |
| `冰箱` → 冰箱内嵌（嵌入插座） | `冰箱(?!内嵌)` |

### 执行与校验

- `re.finditer(r'<table\b[^>]*>.*?</table>', s, re.S)` 取所有表；表头末列后插 `<th>`、每行末列后插 `<td>`。
- 重建文件用「按位置升序拼接 + 每章首个目标表前插注释」，避免索引错位。

  要么最后一次性重跑数据脚本再单独补 CSS，**中途不要 cp 覆盖**。

### 回应外部审核的纪律

1. **先怀疑自己读错行，别先怀疑「行号漂移」**。对方行号是它取证那一版的；等行替换 + 行数恒定在数学上已排除漂移。顺序：`print` 该行真实内容 → 与对方描述比对 → 不符先怀疑自己读错。
2. **验收对方声明前先核对是不是同一命题**。「href 有没有对应 id」（悬空）与「链文本章号 vs 目标宿主章号」是两条断言，**互不覆盖**，不能用一个的通过否定另一个。**这类错误披着「我已验证过」的外衣，最危险**。
3. **语义收敛后按「关键词族」扫**，不按我改过的字面扫（「出远门只断其他分路」/「长期不断电」是同一命题的两种写法，按字面 grep 会漏网）。
4. **备份在每批改动「前」打，不是改完之后**：第十轮两批都缺前置备份 → 审核方无法用 difflib 归批，属不可复原的取证损失。顺序固定 `cp 备份（时间戳） → 改 → 校验 → 报 md5`，备份里的 md5 必须等于改动前。
5. **含「唯一／最／首／最低」必须给比较域**（哪一维、什么量纲）。已栽两次：「唯一硬标准是甲醛」「苯 0.03 是全文最严单项」——同表 PM2.5 0.05、甲醛 0.08 都更低，三氯乙烯 0.006、苯并[a]芘 1.02ng/m³ 更低但不同量纲。改成「限值的比较只在同一量纲内成立」+ 列出该口径最低几项 + 说明跨量纲不可比。
6. **源码换行 ≠ 页面分段**：行首是裸 `<b>`/`<span>` 而非 `<p>`/`<li>` 时，浏览器把换行当空白符，源码看着分段、渲染仍连排。多段并列**每段都要有块级包裹**。

### 引标准的高频错（换版 / 强条接管 / 找原文）

1. **必核「编号 ↔ 名称 ↔ 适用范围」三者**。已犯两次：GB 50189 实为《公共建筑节能设计标准》（只管公共建筑，住宅是 GB 50736-2012），却被写成对住宅的暖通规范；GB 50034 写成强制版，实际是 **GB/T 50034-2024**（推荐性）。**引错标准比引错数值更严重** —— 数值错是验收争议，引错标准审图阶段就退回。同型：把外墙腻子 JC/T 157 的 96h 当内房指标（内房 JG/T 298 是 48h）。→ 写「GB XXXXX《标准名》」前必做：① 编号↔名称对上吗；② 范围含不含当前场景（住宅/公共/工业）；③ 是否被新版代替、强制还是推荐。
2. **写「GB XXXX-20XX 第 N 条」前先查是否已换版**：换版时编号性质（GB↔GB/T）、条号、措辞限定词三样都变。实例：GB 50034-2013 → **GB/T 50034-2024**（2024 年 8 月实施，2013 版废止），LPD 强条并入 **GB 55015-2021**；色温条款 4.4.4-1（无「夜间」限定）→ **4.6.2**「室内夜间长期工作或停留的场所，相关色温不宜高于 4000K」；显色/色容差强制依据在 **GB 55016-2021 3.3.5**。→ 换版后强制属性第一归属挪到 GB 55xxx，50034 只作数值与方法来源。
3. **凡写「规范要求 XX」先查有没有全文强制的通用规范接管**：`GB 55xxx`（55020 给排水、55016 建筑环境、55030 防水、55032 建筑与市政…）优先级高于原设计标准。已栽两次：防水上翻原写 1.8m（实为 JGJ 298-2013 行业下限），现行强条 **GB 55030-2022 4.6.4：淋浴区不应小于 2000mm**、盥洗池盆 1200mm、墙面泛水 250mm；水封深度原引 GB 50015-2019 4.3.10/4.3.11，实为 **GB 55020-2021 4.2.2 强条**接管。→ **行业标准不得冒充 GB 强制值**；引用时写明「强条出处 + 旧版/行业标准数值与两者关系」。
4. **「写推荐却不写依据」是本项目通用病根**：防水上翻「规范要求 1.8m」→ 实为 JGJ 行业下限、强条是 2000mm，且 8 处值不一致；照明色温「推荐 3500K 或 4000K」→ 全书没一处引色温条款，20 处数值互相冲突。→ 写「推荐 XX」前先问**有没有条文、有没有强条**，没有就是随手填的。**补完依据必须回头按关键词族扫同题各处**（每次都是补一处、扫出十几处）；补上出处后「住宅 ≤4000K」这类可验收的线成立，各处冲突自动消解，不必逐处统一数字。
5. **条款按「用途」归位，不能并成一句**：规定值 / 给理由的 / 通用原则三者用途不同。实例：把 4.6.2 条文本体与 4.6 的理由（高色温抑制褪黑素）写成同一句 → 自相矛盾。正确：4.6.2 = 条文本体且限定「夜间」；4.6 = 理由；全屋上限另来自 4.5.1 选色温原则。
6. **「不应检出」与「≤值」要分清**：GB 5749-2022 表 1 微生物 3 项中总大肠菌群、大肠埃希氏菌是「不应检出」，菌落总数 ≤100 CFU/mL —— **「不应检出」只有 2 项**，曾误写 3 项。注 b：小型集中式/分散式供水菌落总数按 500 执行（家用净水不属此列）。→ 写「N 项 X 标准」时逐项确认是「不应检出」「≤某值」还是分级。
7. **找标准原文按渠道可信度排序**：① 政府机关/高校官网 PDF（住建厅审查要点、标准全文）② 标准站与设计院公开全文 PDF ③ 建标库/规范大全类逐字转录站 ④ 商业解读、论坛、问答站 —— 只能当线索，**不可作为数值出处**。

### 写内容时的高频病

- **「绝对化排序」**（最牢固/最便宜/最安全）→ 先问有没有例外。实际**没有绝对最优，只有「和材料/基层/工况匹配」**（玻化砖水泥砂浆厚贴会空鼓脱落、大板砖厚贴自重压出空隙反而更空鼓 → 「厚贴最结实」是错的）。改法：改成「常规做法 / 特殊场景例外」两条并列 + 「排序是匹配 > 工法新旧」。
- **`<strong>` 套 `<strong>`**（已连续违反三次）：外层一律用 `<b>`，内层 strong 才是要强调的那段。嵌套会让标签计数失衡、吞掉外层 `</div>`，而 `validate_html.py` **查不出来**（只有 `strict_stack_check.py` 会报）。改完顺手核 `L[i].count('<strong>') == L[i].count('</strong>')`，`<b>` 同样配平。
- **删子项后没重排圈号** → 出现 `①②③⑤⑥`。已做成常驻断言，但断言有两个已知误报坑（见上节）。
- **heredoc 里的 `\n` 会被 shell 吞成真实换行**：断言串要匹配跨行时用 `LF=chr(10)` 显式构造。
- **交付前行号只当定位线索**：那些行号是对方取证那一版的，我们每批都在同章内改动，行号必然偏移。进脚本前 `print(L[n])` 看真实内容，对不上就用关键词重新定位；**交付时主动说明新行号**，否则对方按旧行号回查全部错位。

## 共用：排版标准（写内容时必须遵守）

判断「用卡片还是用正文」的硬规则：

| 情况 | 用什么 |
|---|---|
| **≥2 个并列的同类名词概念**（字典式速查） | 概念卡片：`item-fold` 折叠块，每条 1–3 句纯定义 |
| **单个复杂概念**（因果、流程、深入讲解） | `h3.sub` 小标题 + 段落正文 |
| **同一组并列概念** | 必须全组同形式，禁止一半卡片一半文字 |
| **只有 1 条概念的折叠块** | 不允许单独存在 → 转成 `h3.sub`+段落，或并入相邻同组卡片 |
| 对比 / 参数 | 表格（必须带 `<colgroup>` 列宽） |
| 有顺序的步骤 / 清单 | `ol.step-list`，不要塞进 callout |
| 警告 / 推荐强调 | callout |

例外：该折叠块所属**系列本身全是折叠块且形式统一**时（如 c14 瓦工验收「一~八」检查项、c02 visual-card 系列），单条也可保留。

**callout 类目定语义，图标可带语义化变体，但不得矛盾**：
`warn`+⚠️（必须避免的错误）· `tip`+💡（技巧/推荐）· `info`+ℹ️（补充说明/清单/索引）· `rec-box`（型号品牌推荐专用）· `err`（硬性禁止，全书仅 1 处）。
⚠️ `warn` 配 💡/✅、`tip` 配 ⚠️ 属矛盾；callout 要点若已抽入正文 `step-list`，不得再保留重复 callout。

## 共用：Python 环境坑

- `re.search(pat, html, pos)` 第三参是 flags 不是 pos → 抛 ValueError，用 `html.find(pat, pos)`。
- `match_tag_pair` 里源码写 `rf"<{tag}\\\\b"` 会变字面 `\\\\b` 匹配不到嵌套 `<div>`，源码须写单反斜杠 `\\b`。
- 章节对调的断言应为 `s1 < e1 <= s2 < e2`，写成 `s2 < e1` 会误判。
- agent-browser 在部分机器上 daemon 起不来（SIGTERM），超时不要恋战，改用 jsdom 探针。
- **别用 `python` / `node` 裸命令**，要写全路径。下面是**占位写法**，两台机器上真实值不同
  （版本号、用户名都会变），本机实测值见 `store/machine/<主机名>/SKILL.md`，**别照抄别台的**：
  Python `C:\Users\<用户>\.workbuddy\binaries\python\versions\<版本号>\python.exe`；
  jsdom 探针 `C:\Users\<用户>\.workbuddy\binaries\node\workspace\jsdom_probe.js`；
  **Node 路径千万别硬编码版本号**：`versions/current` 是**存版本号的文本文件**（内容如 `22.22.2-3`），
  **不是目录**，拼成 `current/node.exe` 会失效。正确写法是读该文件得到版本号再拼
  `versions/<版本号>/node.exe`，读不到再 glob `versions/*/node.exe`。
  硬编码曾让 `_figs/validate_html.py` 的 JS 语法项报 `FileNotFoundError`——表象像 HTML 出问题，实为脚本找不到 node。
- **TOC / 悬浮按钮脚本必须独占一个 `<script>`**：全文共 3 块 script，目录生成（`cleanTitle`）与折叠开合状态机在同一块内，
  任一依赖报错就是整块 `ReferenceError`，症状是「目录点不开 / 悬浮按钮无反应 / 整页交互全失效」。
  改任何 JS 后必须跑 jsdom 探针确认 `window.onerror` 为 0。
- **本 skill 是 `~/.skills/store/local/local-html-kb-maintain` 的软链接**，改它就等于改实体，不需要复制或重挂载。当前 `v0.x`（完善中）可直接增删；只有升到 `v1.0` 才需要用户点头。
